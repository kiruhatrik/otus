# Docker — конспект

## Что такое Docker

**Docker** — это платформа контейнеризации. Она позволяет упаковать приложение вместе со всеми зависимостями в изолированную среду — **контейнер**.

Контейнер — это **не виртуальная машина**, а обычный процесс на ядре хоста, которому навесили ограничения:
- **namespaces** — что процесс видит (свои процессы, файлы, сеть, hostname);
- **cgroups** — сколько ресурсов может потратить (CPU, память).

Docker не придумал ничего нового в ядре, он сделал удобную обёртку: образы, слои, registry, простые команды.

| | Виртуальная машина | Контейнер |
|---|---|---|
| Ядро | своё | общее с хостом |
| Внутри | полная ОС | только приложение и библиотеки |
| Запуск | минуты | секунды |
| Изоляция | сильнее | слабее |

**Главное правило:** контейнер живёт, пока работает его главный процесс (PID 1). Завершился процесс — остановился контейнер.

## Основные команды

```bash
docker run [флаги] ОБРАЗ [команда]   # флаги ВСЕГДА до образа!
docker ps / docker ps -a             # запущенные / все контейнеры
docker logs ИМЯ                      # логи (первое, что смотреть, если упало)
docker exec -it ИМЯ bash             # зайти внутрь (в alpine — sh)
docker stop / start / rm ИМЯ
docker inspect ИМЯ                   # вся информация о контейнере
docker images / pull / rmi / build
docker system prune                  # уборка
```

Флаги `docker run`:
| Флаг | Значение |
|---|---|
| `-d` | в фоне |
| `-it` | интерактивно, с терминалом (для bash, sh, node, python) |
| `--name` | имя |
| `-p 8080:80` | порт **хоста : контейнера** |
| `-v том:/путь` | том |
| `-e КЛЮЧ=значение` | переменная окружения |
| `--network сеть` | сеть |
| `--rm` | удалить после завершения |

**Если контейнер упал:** `docker ps -a` → код в `Exited (N)` → `docker logs ИМЯ`. Ошибка обычно в конце лога.

## Хранение данных

| | Запись | Где данные | Для чего |
|---|---|---|---|
| Volume | `-v pgdata:/var/lib/postgresql/data` | `/var/lib/docker/volumes/` | данные: базы, загрузки |
| Bind mount | `-v /home/vagrant/site:/usr/share/nginx/html:ro` | папка хоста | конфиги, файлы, которые правлю руками |
| tmpfs | `--tmpfs /cache` | в памяти | временное, пропадает при остановке |

- всё, что не в томе, пропадает при удалении контейнера;
- справа в `-v` — путь, куда пишет **программа** (смотреть на Docker Hub). Для postgres — `/var/lib/postgresql/data`, для MariaDB — `/var/lib/mysql`;
- `POSTGRES_PASSWORD` и подобные переменные применяются только при **первом** запуске на пустом томе;
- один том с базой — только одному работающему контейнеру;
- бэкап тома через временный контейнер:
  ```bash
  docker run --rm -v pgdata:/data -v $(pwd):/backup alpine tar czf /backup/pgdata.tgz -C /data .
  ```

## Сети

| | Стандартная `bridge` | Своя сеть (`docker network create`) |
|---|---|---|
| По IP | видят | видят |
| По имени (DNS) | **нет** | **да**, через `127.0.0.11` |
| Изоляция от других сетей | нет | да |

- в своей сети имя контейнера = его адрес. IP меняется при пересоздании, имя — нет;
- контейнер можно подключить к нескольким сетям;
- `host` — сеть хоста без изоляции, `none` — без сети;
- `-p` открывает порт наружу. Базе порт обычно не открывают.

## Dockerfile

| Инструкция | Что делает |
|---|---|
| `FROM` | базовый образ |
| `WORKDIR` | рабочая папка внутри образа |
| `COPY откуда куда` | через **пробел**, «откуда» — от папки сборки |
| `RUN` | команда **при сборке** |
| `ENV` | переменная окружения |
| `EXPOSE` | пометка порта (сам порт не открывает) |
| `USER` | от какого пользователя работать |
| `HEALTHCHECK` | проверка, что приложение живо |
| `CMD ["prog", "arg"]` | команда **при запуске** |

Правила:
- что меняется редко — выше, что часто — ниже (кэш слоёв): сначала `requirements.txt` + `pip install`, потом код;
- в проде: фиксированная версия образа, не root, `.dockerignore`, healthcheck;
- **multi-stage:** в первой стадии собрать, во вторую взять только результат (`COPY --from=build`). Образ Go: 1,34 ГБ → 24,5 МБ.

## Docker Compose

Compose — это записанные в файл команды `docker run` для нескольких контейнеров.

```yaml
services:
  db:
    image: postgres:17
    restart: unless-stopped
    environment:
      POSTGRES_PASSWORD: ${DB_PASSWORD}   # из .env
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD", "pg_isready", "-U", "postgres"]
      interval: 10s
  app:
    build: ./app                          # свой Dockerfile
    depends_on:
      db:
        condition: service_healthy        # ждать готовности базы
    ports:
      - "8080:80"
volumes:
  pgdata:
```

```bash
docker compose config        # проверить файл
docker compose up -d         # поднять / применить изменения
docker compose up -d --build # пересобрать свои образы
docker compose ps / logs
docker compose down          # контейнеры и сеть удаляются, тома остаются
docker compose down -v       # + удаляются тома (данные!)
```

- compose сам создаёт сеть проекта, сервисы видят друг друга по имени сервиса;
- `image` — готовый образ, `build` — свой из папки с Dockerfile;
- `up -d` пересоздаёт только изменившиеся сервисы;
- некоторые приложения помнят свой адрес в базе (WordPress) — при смене порта менять и его.

## Docker и Podman

- **Docker:** клиент `docker` → демон `dockerd` (работает постоянно, от root) → контейнеры — его дочерние процессы. Доступ к `docker.sock` = права root. Упал демон — падают контейнеры.
- **Podman:** без демона. Каждый контейнер — отдельный процесс пользователя, по умолчанию без root (rootless), хорошо дружит с systemd. Команды и образы совместимы с Docker. По умолчанию в RHEL-семействе.

## На чём я спотыкался

- `--it` → правильно `-it` (один дефис — буквы, два — слово);
- флаги после имени образа → уходят внутрь контейнера как аргументы;
- `postgress`, `posgresql` → опечатки в именах образов и путях;
- `"$(pwd)"target` → нужен `/`: `"$(pwd)"/target`;
- `service`, `port`, `volume` в compose → всегда `services`, `ports`, `volumes`, но `image` — без `s`;
- нет `-` у элементов списков (`ports`, `volumes`, `networks`, `depends_on`);
- `COPY a:b` → в Dockerfile через пробел: `COPY a b`;
- `-p 80:8080` вместо `8080:8080` → слева порт хоста, справа порт программы;
- `bad address` по имени → контейнеры в стандартной сети, нужна своя;
- `port is already allocated` → порт занят другим контейнером;
- `DockerFile` → на Linux имя строго `Dockerfile`;
- файл не сохранён в VS Code (Ctrl+S) — compose не видит изменений;
- браузер подставляет `https://` → писать адрес с `http://`.
